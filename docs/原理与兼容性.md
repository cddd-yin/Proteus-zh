# 原理与兼容性说明

## 1. Proteus 的多语言机制

Proteus（8.x 起）使用 **Qt 的 QTranslator 语言包机制** 实现界面多语言：

- 启动时读取系统 UI 语言（`QLocale::system()`），在安装目录 `Translations\` 下按 `proteus_<语言>.qm` 规则加载**应用界面**翻译；Qt 库自身的标准控件翻译为 `qt_<语言>.qm`（出厂自带，如 `qt_zh_CN.qm`）
- 相关证据（8.16 二进制字符串与导入表，可用 `工具/qm_reader.py` 与字符串扫描复现）：
  - `PDS.EXE`：`QTranslator`、`QLocale::system`、`installTranslator`、`Proteus translation loaded`、`Qt translation loaded`、` Translations = ../Translations`
  - `STARTUP.dll`：`Select language pack`、`Use an existing language pack (proteus8lang_xxxx.zip)…`、`Repair language pack`
  - `BIN\LanguagePackInstaller.exe`：处理 `proteus*.qm`，写入 `Translations/`
- 官方还提供**语言包 zip 安装器**（`proteus8lang_<语言>.zip`，由 `LanguagePackInstaller.exe` 或更新管理器安装）。本仓库当前分发「直接投放 qm」的方式，效果等价。

因此：**「切换界面语言」＝「安装语言包」**。系统里没有中文包时，软件设置里也没有「中文」可选项。

## 2. QM 文件格式（本项目的编译目标）

`.qm` 是 Qt 的二进制翻译文件。我们对照了 **Qt 4.8.7 / 5.6.3 / 5.7.0 / 6.7** 四代加载器源码，并解析了两份真实汉化包（2014 风包、picdupe 9.x 包），确认 Proteus 用到的部分**四代格式一致**：

```
magic (16B): 3C B8 64 18 CA EF 9C 95 CD 21 1C BF 60 A1 BD DD
[0x42] Hashes   : N × (u32 elfHash(原文+注释), u32 消息偏移)，按 hash 升序
[0x69] Messages : 逐条记录：03 译文(UTF-16BE) / 08 注释(UTF-8) / 06 原文(UTF-8) / 07 上下文(UTF-8) / 01 结束
[可选] 0x2f Contexts / 0x88 NumerusRules / 0x96 Dependencies / 0xa7 Language
```

- 查询流程：以 `elfHash(原文+注释)` 二分哈希表 → 在候选记录中校验「原文 + 上下文」完全一致 → 取译文
- 关键点：**上下文（context）必须与程序内部调用时完全一致**，因此词库按 `(context, source)` 精确匹配
- 经典 2014 包不含 `Contexts` 预过滤节，加载器将其视为可选；本项目编译产物同样省略该节（结构最简，已实测可加载）
- `工具/qm_writer.py` 即为上述格式的**纯 Python 编译器**，无需 Qt 工具链（开发期曾用 `lrelease` 交叉验证，产物行为一致）

## 3. 上下文（context）代际差异与「一份文件通吃」

| 代际 | 典型上下文 | 说明 |
| --- | --- | --- |
| 8.x 传统层 | `MENU:`、`RST: ISIS\File`、`DLG: ARES\OP_PRINT`、`CMD: …` | Proteus 自研字符串/命令/对话框翻译层 |
| 8.x / 9.x Qt 层 | `HomePage`、`HomePageClass`、`SrcManager`、`ProgramSettingsDialog`… | C++ 类名（`tr()` 默认上下文） |
| 9.x 新命名 | `IsisCmds::FileCmds`、`ARES_File`、`PPCDialog`… | 9.x 重构后的类/命名空间命名 |

不同代的程序设计不同，但**查找机制相同且互不干扰**：把多代词条全部装进同一 `proteus_zh_CN.qm`，各版本运行时只会命中属于自己的上下文，其余条目自然闲置——这就是「一份文件、多代通用」的原理。

> 实测佐证：Proteus 8.16 会同时命中 `HomePageClass`（8.x 传统）与 `HomePage`（新式）两类上下文；`MENU:` 控制主菜单栏、`CMD:` 控制命令描述、`RST:`/`DLG:` 控制各模块资源与对话框。

## 4. 已知限制

- **上下文漂移**：新版重命名类/资源时，旧词条不再命中（表现为个别位置仍为英文）。解决方式 = 提取新版本词条并补译（`build_pack.py` 流程）
- **运行时拼接文本**：程序内部以代码拼装、且未走翻译层的字符串（如部分状态栏提示）无法通过语言包覆盖
- **复数/占位符**：中文无复数变体，本项目按单形式编译；含 `%n` 的词条取第一条译文
- **字体**：个别对话框若使用窄字体，长中文可能显示拥挤（与语言包无关，正常现象）
